# Перший запуск — ESP32-S3 Smart UPS Monitor v3.9

Документ описує практичний стенд, а не універсальний готовий UPS. Спочатку прочитайте [SAFETY.md](SAFETY.md) та [HARDWARE.md](HARDWARE.md).

## 1. Що знадобиться

- ESP32-S3-DevKitC-1, комп'ютер із VS Code + PlatformIO, USB-кабель.
- INA226 з шунтом R010 (0,01 Ом), YX850, LM2596, розраховані дільники напруги, безпечно підключені джерела живлення.
- Wi-Fi; для Telegram — інтернет, NTP, власний бот і chat ID.
- Конфігурація пам'яті у `platformio.ini`: 16 MB Flash + 8 MB OPI PSRAM. Перевірте відповідність саме вашій платі.

## 2. Налаштування

Відкрийте клон репозиторію у VS Code. У PowerShell виконайте:

```powershell
Copy-Item include\secrets.example.h include\secrets.h
```

У створеному **локальному** `include/secrets.h` задайте власні `WIFI_SSID`, `WIFI_PASSWORD`, `OTA_PASSWORD`, `TELEGRAM_BOT_TOKEN` та `TELEGRAM_CHAT_ID`. Приклад не містить робочих облікових даних. Наразі код v3.9 вимагає макроси Telegram для компіляції, навіть якщо ви не користуєтеся ботом.

Зверніть увагу: перевірена конфігурація `platformio.ini` містить **COM3** та **192.168.0.103** — це параметри конкретного стенда, не універсальні значення. Змініть їх відповідно до своєї системи.

## 3. Збірка та початкове прошивання

```powershell
pio run -e esp32s3
```

Для **першого** завантаження через USB змініть у `platformio.ini` `upload_protocol = espota` на `upload_protocol = esptool`, вкажіть актуальний `upload_port = COMx` і виконайте `pio run -e esp32s3 -t upload`. Правильно виберіть пам'ять і розділи Flash; невідповідність `partitions.csv` потребує окремого тестування через USB.

Коли ESP32 під'єднається до Wi-Fi, для наступних оновлень поверніть `upload_protocol = espota` та вкажіть її реальну IP-адресу в `upload_port`. У **локальному** файлі `ota_password.txt` задайте той самий пароль, що в `OTA_PASSWORD` (`include/secrets.h`); `ota_upload.py` прочитає його автоматично. Файл `ota_password.txt` виключено з Git.

## 4. Перевірка

- Відкрийте вебпанель за IP ESP32; перевірте чотири вкладки: «Головна», «Журнал», «Аналітика», «Система».
- Надішліть Telegram-боту `/status` і `/battery`.
- `/schedule` наразі працює з **неофіційним** графіком **Полтавська область, черга 1.2**. Регіон і константа `OUTAGE_GROUP = "GPV1.2"` у коді не підлаштовуються автоматично під інших користувачів.
- На момент випуску v3.9 автоматичні нагадування за 60/15 хвилин не мали окремого реального часового тесту; у польовому використанні 22–23.11.2026 такі нагадування **фактично надходили**. Для інших користувачів спрацювання залежить від інтернету, NTP та неофіційного джерела. Див. [звіт польового тесту](FIELD_TEST_2026-11-22_23.md).
- Спочатку мультиметром перевірте живлення логіки, кожен дільник та виходи LM2596; лише потім тестуйте перемикання, допускаючи перезапуск навантаження.

**Не додавайте до Git** `include/secrets.h`, `ota_password.txt`, реальні токени, паролі та дампи NVS. Перед комітом перевірте `git status --short` і `git diff --cached`.
